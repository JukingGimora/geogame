# 运维手册

> 记的是踩过的坑和不看文档就会做错的操作。常规的东西(怎么写 Python、怎么用 git)不记。

## 1. 部署

```bash
cd ~/projects/geogame && git pull
# 如有本次需要的迁移(见第 2 节),在重启之前执行
sudo systemctl restart geogame-backend
./scripts/smoke.sh https://tz5aq2zkxqhc.guyubao.com    # 必跑
```

**冒烟脚本一定要跑。** 少导入一个名字、删了函数忘改调用方,这类错误在本地跑一条正常
路径完全发现不了,但接口一请求就 500。已经因此在线上挂过两次:`/auth/me`(每个页面
都调,挂了直接黑屏)和 `/admin/stats`。脚本把 21 个接口全打一遍,不全绿就别发布。

前端要另外构建。**只有 `dist/build/mp-weixin` 是上传用的产物**:

```bash
cd frontend && npm run build:mp-weixin   # 产物 dist/build/mp-weixin
```

`npm run dev:mp-weixin` 产出的是 `dist/dev/mp-weixin`,那是本地热更新用的。**微信开发者工具的项目目录必须指向 `dist/build/mp-weixin`**——曾经因为工具里指着 `dist/dev`、而这边一直在跑 `build`,导致连续几轮"改了没生效"的误判,浪费了很多时间。

## 2. 数据库迁移

后端建表用的是 `Base.metadata.create_all`,它**只建新表,不会给已存在的表加列**。所以每次给模型加字段,线上都要手工执行一次 ALTER。

已执行过的:

| 时间 | 变更 |
|---|---|
| 2026-07-30 | `photos.file_hash VARCHAR(64)` + 索引 `ix_photos_file_hash`(照片查重) |

注意两点:

- **ALTER 要在 `restart` 之前跑完。** 先重启的话,新代码查一个还不存在的列,所有涉及照片的接口(上传、审核列表、我的行囊)会全部报错。
- `sqlite3` 一行里多条语句,**前一条报错会中止后面的**。所以 `ALTER ...; CREATE INDEX ...;` 如果列已存在,索引那句不会执行,要单独再跑一次。

## 3. 审核流程

1. 打开 `/admin`,填管理口令(`GEOGAME_ADMIN_TOKEN`)
2. 点 **「补算AI」** —— 每次最多 20 张。**只有这一步花 AI 的钱**
3. 逐张看:上传者标注 vs AI 推测,偏差超 300km 会标橙色「⚠ 可能标错地点」
4. 通过 / 拒绝

**AI 推理是手动触发的,不在上传时自动跑。** 因为上传是开放的,谁都能一次推几十张,自动跑等于让还没人看过的垃圾图也烧 API 费用。被拒的图只要没提前补算过,一分钱不花。

「通过」时如果发现这张还没有 AI 数据,会现算一次兜底(那次要等约 5 秒),保证不会有 live 图缺 AI 对手。补算过的话审批是瞬间的(实测 0.024s)。

橙色警告会有**误报**:AI 自己也会猜错(实测过一张秦岭的照片,AI 高置信度地答成北京西山,偏 920km)。所以它只表示"这张值得多看一眼",不是判决——旁边一并显示了 AI 的推理文本,方便快速排除。

## 4. 只能用 curl 调的运维接口

没做成按钮的一次性/低频操作。都要带 `-H "X-Admin-Token: $GEOGAME_ADMIN_TOKEN"`。

```bash
# 给缺 file_hash 的老照片补哈希(不补则老图不参与重复上传检测)。
# 2026-07-30 已对当时的存量执行完毕;留着是为了将来数据导入之类的场景。
curl -X POST "http://localhost:8020/api/v1/admin/photos/backfill-hashes?limit=500" \
  -H "X-Admin-Token: $GEOGAME_ADMIN_TOKEN"

# 看数据:次日留存、分享率、资料完善转化率、AI 对手胜率
curl -s "http://localhost:8020/api/v1/admin/stats" -H "X-Admin-Token: $GEOGAME_ADMIN_TOKEN" | python3 -m json.tool
```

## 4.5 批量导入自己的照片

手机端的上传接口一次一张、还要手动在地图上点位置、每天 20 张封顶,几百张存量传不完。
用 `tools/import_photos.py`:坐标直接从照片的 EXIF 里读。

```bash
export GEOGAME_ADMIN_TOKEN=...
python3 tools/import_photos.py ~/Downloads --uploader 17 --dry-run   # 先空跑,看多少张带坐标
python3 tools/import_photos.py ~/Downloads --uploader 17             # 真导入,状态是待审核
```

- **照片必须用隔空投送或数据线传到电脑。** 经微信中转的图 GPS 会被抹掉,导进去没有坐标。
- **iPhone 的 HEIC 需要 `pip install pillow-heif`**,否则读不出 EXIF,会全部误判成"没有坐标"。
- 重复的图按 sha256 自动跳过,不会重复入库。
- 导入的照片没有故事,在审核页用 `POST /admin/photos/{id}/story` 补写(会同时更新提示①)。

## 4.6 小程序上传拿不到照片的 GPS——这是微信的行为,别再试了

**小程序里的上传永远要用户自己在地图上标位置。** 试过把 `chooseMedia` 的
`sizeType` 从 `compressed` 换成 `original`,没有用:

| 日志 | 说明 |
|---|---|
| `JPEG 3024x4032 2142173B EXIF字段=5 无 GPS 段` | 满分辨率原图确实传上来了 |
| `JPEG 4284x5712 3500794B EXIF字段=5 无 GPS 段` | EXIF 还在,但 GPS 那一段已经没了 |

已确认这两张在相册里都带定位。**微信在把文件交给小程序之前就把 GPS 摘掉了**,
跟 4.5 节说的"经微信中转的图 GPS 会被抹掉"是同一件事。所以:

- 在小程序里做客户端 EXIF 解析没有意义——那几个字节根本没进来
- 换原图只换来 2~3.5MB 的上传,把上传变慢,一个坐标也读不到
- H5 保持 `original`:那边是浏览器直接给真文件,服务端确实能读出坐标

每次退回手动标位置,日志都会写一行 `need_location:`,里面说清是"无 EXIF"
(被转码剥掉)还是"无 GPS 段"(拍的时候没开定位),以后不用再猜。

## 4.7 H5 是英文版,小程序是中文版

H5 给的是外语用户,默认英文;`?lang=zh` 切回中文并记在浏览器里,**中文版没有删**。
一个构建产物装两种语言,不是两份 H5——两份要各自构建各自部署,改一个字迟早漏一边。
小程序把英文文案整个编译掉了(`locale/index.ts` 里的条件编译),包里搜不到一个英文词。

界面文案在 `frontend/src/locale/{zh-CN,en}.ts`。**新加文案两个文件都要加**;
漏了的那一边会直接把 key 当字符串显示出来(页面上冒出个 `map.noLives`),
而且构建不会失败,只能靠查。加完跑一下:

```bash
python3 scripts/check-locale.py    # 漏的 key、两边对不齐的 key,都会列出来
```

后端吐出来的中文按请求头 `X-Lang` 换:文化圈描述、国名、提示③④、新账号的随机昵称。
**文化圈的名字永远是中文**——它同时是配色表的键和开局回传的 chapter,只有显示那一面翻译,
对照表在两个语言文件的 `circles` 段里。

故事(提示①)和 AI 线索(提示②)是内容不是模板,只能预先翻好存进 `hint_translations`:

```bash
cd backend
python3 ../tools/translate_hints.py --dry-run                    # 看要翻多少
python3 ../tools/translate_hints.py --limit 5                    # 先五条,人眼看
python3 ../tools/translate_hints.py --model qwen3.7-flash        # 全量
python3 ../tools/translate_hints.py --redo                       # 换了 prompt 或模型后重翻
```

- **没有译文就照原样显示中文。** 宁可露一句中文,也不能让这一关没有提示。
- **`qwen-mt-*` 不收 system 角色**(直接 400),约束只能塞进 `translation_options.domains`。
  通用模型走 system prompt,约束更硬,所以默认用 `qwen3.7-flash` 并关掉思考
  (不关的话一条 87 字的句子要烧两千多个思考 token)。
- **译文不许点原文没点的国家。** 实测过:中文只说"北方某超大城市",第一版译成
  "a megacity in northern China" ——国家是提示③、单收四成分,线索②里泄出来等于打折卖答案。
  prompt 里写死了这条,脚本跑完还会自动比一遍国名和族称,可疑的列出来让人看。

## 5. 换 AI 模型

改 `.env` 里的 `GEOGAME_AI_MODEL` 再重启即可,不用动代码。

但 `GEOGAME_AI_BASE_URL` 目前是个**专属部署地址**,不是百炼公共入口,上面的模型不是都能用。换之前先验证连通性:

```bash
# 列出该端点可用的模型
curl -s "$GEOGAME_AI_BASE_URL/models" -H "Authorization: Bearer $GEOGAME_AI_API_KEY" \
  | python3 -c "import sys,json;[print(m['id']) for m in json.load(sys.stdin)['data']]"
```

**2026-09-14 从 `qwen3-vl-plus` 换成 `qwen3.7-flash`**(前者 10.10 下架)。选它的理由是**便宜且够用**,不是最准:

| 模型 | 输入/输出 元/百万token | 每张照片约 | 8 张线上照片实测 |
|---|---|---|---|
| `qwen3-vl-plus`(旧) | 1 / 10 | 0.7 分 | — |
| `qwen3.7-plus` | 2 / 8 | 1.2 分 | 全成功,5-7 秒 |
| `qwen3.7-flash` 思考开 | 0.2 / 0.8 | 0.6 分 | 25-47 秒,1 张超时 |
| **`qwen3.7-flash` 思考关(当前)** | 0.2 / 0.8 | **0.1 分** | 全成功,2-7 秒 |

每张照片调两次(AI 猜测 + 提示②),单次约 2000 输入 token(图片占 1900)。价格以百炼控制台为准。

- **请求里固定带 `enable_thinking: false`**。qwen3.7 系列默认先思考,每次多出两三千 token,慢到超时,准确度也被推高——AI 对手本来就偏强(8/1 胜率 64.7%),更强反而不合适。`qwen-vl-max`、`qwen3-vl-flash`、`qwen3.7-plus` 带这个参数也不报错。
- **模型失效是静默的**:调用失败只返回空,不报错。表现是新补算的照片没有 AI 对手、提示②变成兜底文案。所以换完一定要挑一张待审照片点「补算AI」,在审核页确认有 AI 推测。
- 选模型看 `/admin/stats` 的 `ai_duel.ai_win_rate`(理想 30-40%),不看准确度。

早先(7 月)实测过:`qwen3.7-max` 报参数错误、`ZHIPU/GLM-5.2` 提示未开通。**换模型可能需要连 base_url 一起换。**

## 6. 排查故障:先看真实异常

上传报错基本都是这几种,**别靠猜,日志里有真因**:

```bash
sudo journalctl -u geogame-backend -n 100
```

| 现象 | 含义 |
|---|---|
| `503 storage_unavailable` | 存储写不进去。**优先查阿里云账号余额**——曾因欠费被停用(`Code: UserDisable`),OSS 拒绝一切读写 |
| `422 invalid_image` | 图片本身解不开(格式不认) |
| `422 invalid_coordinates` | 坐标超出经纬度范围 |
| `413 file_too_large` | 超过 15MB。前端已强制用压缩版上传,正常不该触发 |
| `409 duplicate_photo` | 这张图已经在题库里(`pending`/`live`)。被拒的图会释放占用,可以重传 |
| `detail` 是个**数组** | FastAPI 的表单校验失败,通常是没选拍摄地就提交 |

OSS 停用那次,现象是"上传失败 422",而提示文案是"这张图片打不开,换一张试试"——用户会一直换图,而换哪张都不可能成功。所以**存储故障和图片损坏必须分开报**,现在已经分开了(503 vs 422)。

## 7. 本地开发

后端跑在 **base conda 环境**,不是 `geogame` 环境(`geogame` 里没装 `oss2`,用它启动会直接崩)。
`Settings` 会读当前目录的 `.env`(所以 `tools/` 下的脚本要在 `backend/` 里跑),
真的环境变量优先级更高:

```bash
cd backend
set -a; source .env; set +a
/opt/anaconda3/bin/uvicorn app.main:app --host 0.0.0.0 --port 8020
```

**改了 `.env` 或代码必须重启进程**,环境变量只在启动时读一次。曾经因为改了 `.env` 没重启,排查了半天"管理口令 403"。

`admin.html` 已设 `Cache-Control: no-cache`,改完刷新即可生效,不用再强刷。
