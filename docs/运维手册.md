# 运维手册

> 记的是踩过的坑和不看文档就会做错的操作。常规的东西(怎么写 Python、怎么用 git)不记。

## 1. 部署

```bash
cd ~/projects/geogame && git pull
# 如有本次需要的迁移(见第 2 节),在重启之前执行
sudo systemctl restart geogame-backend
./scripts/smoke.sh https://tz5aq2zkxqhc.guyubao.com    # 必跑
```

**冒烟脚本一定要跑。** 少导入一个名字、删了函数忘改调用方,这类错误在本地跑一条正常
路径完全发现不了,但接口一请求就 500。已经因此在线上挂过两次:`/auth/me`(每个页面
都调,挂了直接黑屏)和 `/admin/stats`。脚本把 21 个接口全打一遍,不全绿就别发布。

前端要另外构建。**只有 `dist/build/mp-weixin` 是上传用的产物**:

```bash
cd frontend && npm run build:mp-weixin   # 产物 dist/build/mp-weixin
```

`npm run dev:mp-weixin` 产出的是 `dist/dev/mp-weixin`,那是本地热更新用的。**微信开发者工具的项目目录必须指向 `dist/build/mp-weixin`**——曾经因为工具里指着 `dist/dev`、而这边一直在跑 `build`,导致连续几轮"改了没生效"的误判,浪费了很多时间。

## 2. 数据库迁移

后端建表用的是 `Base.metadata.create_all`,它**只建新表,不会给已存在的表加列**。所以每次给模型加字段,线上都要手工执行一次 ALTER。

已执行过的:

| 时间 | 变更 |
|---|---|
| 2026-07-30 | `photos.file_hash VARCHAR(64)` + 索引 `ix_photos_file_hash`(照片查重) |

注意两点:

- **ALTER 要在 `restart` 之前跑完。** 先重启的话,新代码查一个还不存在的列,所有涉及照片的接口(上传、审核列表、我的行囊)会全部报错。
- `sqlite3` 一行里多条语句,**前一条报错会中止后面的**。所以 `ALTER ...; CREATE INDEX ...;` 如果列已存在,索引那句不会执行,要单独再跑一次。

## 3. 审核流程

1. 打开 `/admin`,填管理口令(`GEOGAME_ADMIN_TOKEN`)
2. 点 **「补算AI」** —— 每次最多 20 张。**只有这一步花 AI 的钱**
3. 逐张看:上传者标注 vs AI 推测,偏差超 300km 会标橙色「⚠ 可能标错地点」
4. 通过 / 拒绝

**AI 推理是手动触发的,不在上传时自动跑。** 因为上传是开放的,谁都能一次推几十张,自动跑等于让还没人看过的垃圾图也烧 API 费用。被拒的图只要没提前补算过,一分钱不花。

「通过」时如果发现这张还没有 AI 数据,会现算一次兜底(那次要等约 5 秒),保证不会有 live 图缺 AI 对手。补算过的话审批是瞬间的(实测 0.024s)。

橙色警告会有**误报**:AI 自己也会猜错(实测过一张秦岭的照片,AI 高置信度地答成北京西山,偏 920km)。所以它只表示"这张值得多看一眼",不是判决——旁边一并显示了 AI 的推理文本,方便快速排除。

## 4. 只能用 curl 调的运维接口

没做成按钮的一次性/低频操作。都要带 `-H "X-Admin-Token: $GEOGAME_ADMIN_TOKEN"`。

```bash
# 给缺 file_hash 的老照片补哈希(不补则老图不参与重复上传检测)。
# 2026-07-30 已对当时的存量执行完毕;留着是为了将来数据导入之类的场景。
curl -X POST "http://localhost:8020/api/v1/admin/photos/backfill-hashes?limit=500" \
  -H "X-Admin-Token: $GEOGAME_ADMIN_TOKEN"

# 看数据:次日留存、分享率、资料完善转化率、AI 对手胜率
curl -s "http://localhost:8020/api/v1/admin/stats" -H "X-Admin-Token: $GEOGAME_ADMIN_TOKEN" | python3 -m json.tool
```

## 5. 换 AI 模型

改 `.env` 里的 `GEOGAME_AI_MODEL` 再重启即可,不用动代码。

但 `GEOGAME_AI_BASE_URL` 目前是个**专属部署地址**,不是百炼公共入口,上面的模型不是都能用。换之前先验证连通性:

```bash
# 列出该端点可用的模型
curl -s "$GEOGAME_AI_BASE_URL/models" -H "Authorization: Bearer $GEOGAME_AI_API_KEY" \
  | python3 -c "import sys,json;[print(m['id']) for m in json.load(sys.stdin)['data']]"
```

实测过:`qwen3.7-max` 报参数错误、`ZHIPU/GLM-5.2` 提示未开通、`qwen3.7-plus` 超时。真正可用的视觉模型是 `qwen3-vl-plus`(当前)、`qwen3-vl-plus-2025-12-19`、`qwen3-vl-flash`、`qwen-vl-max`。**换模型可能需要连 base_url 一起换。**

## 6. 排查故障:先看真实异常

上传报错基本都是这几种,**别靠猜,日志里有真因**:

```bash
sudo journalctl -u geogame-backend -n 100
```

| 现象 | 含义 |
|---|---|
| `503 storage_unavailable` | 存储写不进去。**优先查阿里云账号余额**——曾因欠费被停用(`Code: UserDisable`),OSS 拒绝一切读写 |
| `422 invalid_image` | 图片本身解不开(格式不认) |
| `422 invalid_coordinates` | 坐标超出经纬度范围 |
| `413 file_too_large` | 超过 15MB。前端已强制用压缩版上传,正常不该触发 |
| `409 duplicate_photo` | 这张图已经在题库里(`pending`/`live`)。被拒的图会释放占用,可以重传 |
| `detail` 是个**数组** | FastAPI 的表单校验失败,通常是没选拍摄地就提交 |

OSS 停用那次,现象是"上传失败 422",而提示文案是"这张图片打不开,换一张试试"——用户会一直换图,而换哪张都不可能成功。所以**存储故障和图片损坏必须分开报**,现在已经分开了(503 vs 422)。

## 7. 本地开发

后端跑在 **base conda 环境**,不是 `geogame` 环境(`geogame` 里没装 `oss2`,用它启动会直接崩)。而且 `Settings` 不会自动读 `.env`,要先 source:

```bash
cd backend
set -a; source .env; set +a
/opt/anaconda3/bin/uvicorn app.main:app --host 0.0.0.0 --port 8020
```

**改了 `.env` 或代码必须重启进程**,环境变量只在启动时读一次。曾经因为改了 `.env` 没重启,排查了半天"管理口令 403"。

`admin.html` 已设 `Cache-Control: no-cache`,改完刷新即可生效,不用再强刷。
